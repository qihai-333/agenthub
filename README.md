# AGENT HUB

一个 Windows 上的「AI 应用工作台」：左侧一条窄侧栏，点谁就把谁的真实窗口铺到右侧，切换只是显示/隐藏，不重启、不丢状态。

> 不是网页聚合器。它接管的是**应用本身真实的窗口**，所以登录态、会话、正在跑的任务都原样保留。

## 它解决的问题

日常要在豆包、Trae、Qoder、Codex、DSH 之间来回切，窗口越开越多、Alt+Tab 里全是它们。

AGENT HUB 把它们收进一条侧栏：

- 同时最多选入 **3 个**应用，点一下切过去，再点一下换回来
- 侧栏固定 92px，窗口关掉后**滑出到屏幕左边**，靠托盘图标或左边缘 3px 唤回
- 托盘图标常驻：左键唤回，右键有「显示 / 重新加载 / 打开日志 / 退出」
- 启动时图标像一叠卡片展开；**谁被用过就自动浮到最上面**（顺序会记住）
- 没选应用时，内容区是工作模式选择页：多 agent 协同 / 普通工作站二选一
- 退出时结束**所有已选**的应用（三个全关，不留后台）
- 下次启动自动恢复上次的三个

## 操作

| 操作 | 效果 |
|---|---|
| 左键点图标 | 未选 → 选入并显示；已选 → 切过去 |
| 右键点图标 | 取消 / 编辑 / 移除（后两项只对自己添加的应用） |
| `Alt` + `1`~`9` | 等同左键点第 N 个 |
| 鼠标碰到屏幕最左缘的 3px 热区 | 侧栏滑出后自动展开 |
| 底部虚线「+」 | 添加应用 |
| 左下角电源图标 | **关到后台**（侧栏滑出、应用隐藏、进程继续跑） |
| 侧栏底部「协」 | 进入 / 退出多 agent 协同模式 |

## 名额

同时最多 3 个已选，判定标准是**进程存活**：

- 选满 3 个后再点第四个 → 底部弹一条提示，不打断你
- 右键「取消」= 结束整棵进程树 + 释放名额
- 应用自己关掉窗口（包括缩进托盘）→ 2 秒内自动释放名额

## 添加自己的应用

点底部「+」：

- 上半部分列出**当前所有可见窗口**，选一行，名称和程序路径自动填好
- 也可以直接填或浏览 exe 路径（应用没开着时用这条）

添加后写入 `custom.json`，不污染 `agents.json`。

## 多 agent 协同

点侧栏底部的「协」进入。三个应用各司其职，走完一轮"拆解 → 执行 → 自检 → 对齐"：

```
                  ┌─────────── 回到 1（算新一轮，须你确认） ───────────┐
                  │                                                     │
需求 →[① 拆解]→[② 执行]→[③ 自检]→[① 对齐：总结/剩余问题/下一轮建议]
         Agent 1      Agent 2      Agent 3              Agent 1
```

**怎么走一轮：**

1. **选角色**：点侧栏选三个应用——第 1 个 = 需求拆解，第 2 个 = 任务执行，第 3 个 = 完成自检（拆解和最终对齐都由第 1 个承担）
2. **填需求**：上方是多行输入框，点「开始协同」创建会话；空需求会明确提示，不会误启动
3. **接力**：每步程序切到对应应用的窗口 + 把阶段提示词放进剪贴板，你 `Ctrl+V` 回车干活；在应用里 `Ctrl+C` 复制回复，程序自动捕获推进（捕获不到就点底部「手动推进」）
4. **步级确认**：某步完成后对应卡片变绿出现「确认 → 交给…」，点开自动接力开关（`pipeline.json` 里 `autoAdvance`）则跳过逐步确认
5. **轮末必停**：最终对齐完成才计一轮，随后必须你点「继续下一轮 / 补充需求后继续 / 结束协同」，绝不自动循环；下一轮自动带上原始需求、此前成果、自检问题、对齐结论和你的补充
6. **看对话**：点卡片（或卡上「查看对话 / 补充需求」）打开该应用的对话窗——记录里是它真实回复过的内容；输入的补充会注明来源、时间，在下一次交接时真实进入提示词
7. **右侧面板**：当前轮次 / 已完成轮数 / 当前阶段 / 各轮结论（点开看完整记录）
8. **失败与停止**：应用启动失败或超时 → 流程停住、展示原因，可「重试当前步」（无副作用）或「结束协同」；「停止」随时可恢复。会话记录在右侧和 `.scratch\pipeline-<时间>.md` 都保留

`pipeline.json` 可改四个阶段的提示词（占位符：`{{task}}` `{{decomposition}}` `{{execution}}` `{{selfcheck}}` `{{history}}` `{{additions}}`），结构固定四段式。老的 `pipeline.json` 想换新模板可删掉让它重建。

## 下载后怎么用

从 [Releases](https://github.com/mihayoufamily/agenthub/releases) 下载 `AgentHub-1.0.0-win64.zip`，解压后双击 `AgentHub.exe`。

- 不需要装 .NET SDK，不需要任何运行时，单文件不到 500KB
- **首次运行是模式选择页 + 空侧栏**，点侧栏底部的「+」添加你的应用：可以从当前打开的窗口里挑，也可以手填 exe 路径
- 添加的应用写进同目录的 `custom.json`，下次启动自动恢复上次打开的三个

> 仓库里的 `bin/` 是构建产物、不进 git，所以**直接下源码 zip 是找不到 exe 的**——要么下 Release，要么自己编。

## 从源码构建

双击 `build.bat` 就行，它会调用 Windows 自带的 .NET Framework 4 编译器（Win10/11 都有）：

```bat
build.bat
```

产物 `bin\AgentHub.exe`。

也可以用 PowerShell 版 `build.ps1`，但如果提示"禁止运行脚本"，先执行一次：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
```

## 运行

把 `AgentHub.exe` 单独放到一个目录就行（**不要放在被沙箱管辖的工作区里**，否则进程会拿到低完整性令牌，表现为点应用一直"正在启动"）。

```powershell
.\bin\AgentHub.exe
```

没有 `agents.json` 时从空白开始，用「+」添加应用。

## 配置

`agents.json` 是内置应用列表（`agents.example.json` 是模板）：

```json
{
  "id": "doubao",
  "name": "豆包",
  "short": "豆",
  "kind": "exe",
  "exe": "C:\\Path\\To\\Doubao.exe",
  "proc": "Doubao",
  "title": "豆包",
  "frame": "offset"
}
```

| 字段 | 说明 |
|---|---|
| `exe` | 可执行文件，也可写 `.lnk` 快捷方式 |
| `proc` | 进程名，多个用逗号分隔 |
| `title` | 窗口标题包含该串也算命中（进程名拿不到时的兜底） |
| `frame` | 省略 = 去掉标题栏；`offset` = 保留边框、把非客户区推到屏幕外（给 WebView2/Tauri 类窗口用） |

`custom.json` 由界面里添加的应用自动写入，格式相同。

`pipeline.json` 是协同模式的流程定义（首次进协同模式时自动生成，之后每次进入都会重读）：

```json
{
  "maxRounds": 3,
  "stepTimeoutMinutes": 10,
  "steps": [
    { "role": "拆解", "agent": "dsh",  "prompt": "拆解这个需求为可执行的编码任务：{{task}}" },
    { "role": "编码", "agent": "trae", "prompt": "按下面的任务写代码，只输出代码和必要说明：{{input}}" },
    { "role": "审查", "agent": "qoder","prompt": "审查下面的代码是否满足任务要求：{{input}}" },
    { "role": "判定", "agent": "dsh",  "prompt": "判断任务是否完成，第一行只写「满足」或「不满足」：{{input}}" }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `maxRounds` | 安全上限（默认 10），达到后「继续」拒绝，只能结束 |
| `stepTimeoutMinutes` | 某步超过这么久没动作就自动暂停 |
| `autoAdvance` | 步级接力是否自动确认；轮级永远停在用户确认处 |
| `steps` | 四个阶段的提示词；占位符 `{{task}}`（需求）`{{decomposition}}`（拆解）`{{execution}}`（执行）`{{selfcheck}}`（自检）`{{history}}`（历史轮次）`{{additions}}`（用户补充） |

## 出问题时

日志在 exe 同目录的 `data\app.log`（用 `--config` 启动的实例在 `data-<配置名>\`），关键行：

```
start doubao            ← 点了哪个
found doubao hwnd=...   ← 找到的窗口（标题兜底命中时会打这行，可核对有没有认错）
find: title match rejected ... ← 标题兜底拦掉了一次疑似误匹配
apply ... offset=False  ← 开始接管
apply rejected: ...     ← 窗口拒绝被移动，后面 want= 是期望位置
park 0 ok=True ...      ← 协同模式把窗口停到虚拟桌面外
drop dsh window-gone    ← 应用自己关掉了，已释放名额
```

如果窗口被留在半接管状态（程序异常退出），运行 `AgentHub.exe --restore` 还原。
`AgentHub.exe --doctor` 会输出一份环境自检报告。

## 已知限制

- 只支持 Windows（依赖 `SetWindowPos` / 窗口样式 / 进程树操作）
- 应用以管理员权限运行时，本程序需要同等权限才能接管它的窗口
- 个别应用会拒绝被移动，或自己恢复窗口大小（表现为铺不满）
- 只接管顶层窗口，不接管浏览器标签页
- 侧栏和内容区只出现在**主显示器**（协同停靠按整个虚拟桌面计算，不会露到副屏上）
- 协同模式靠剪贴板接力：程序只切窗口、放提示词，粘贴、回车、复制回复都要手动
- 不建议同时运行两个实例：不同 `--config` 的数据目录已互相隔离，但全局热键归先启动的那个

## 状态

主程序与源码已发布（[Releases](https://github.com/mihayoufamily/agenthub/releases)）。协同模式备注：

- 平铺用的 DWM 缩略图对"注册哪个句柄"很敏感——多窗口应用（Chromium 系）常有隐藏主窗，程序会在注册前核对源窗口可见性，不对就自动换（日志里搜 `thumb ... reswitch`）
- 侧栏状态收敛为单一枚举（`DockState`：Visible / Hidden / Background），滑出动画只是进度条，不再有三个布尔变量打架
- Trae 启动问题的旧结论（"Trae 自己的问题"）已作废：当时的测试命令跑在沙箱作业对象里，Chromium 嵌套作业会失败。请在正常启动的 AgentHub 里重验
