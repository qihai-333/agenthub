# 运行期数据按实例隔离

`--config <文件>` 启动的实例，运行期数据放在 exe 旁的 `data-<配置名>\`；默认实例仍用 `data\`。

## 背景

之前 session.json、journal.txt、app.log 全部固定在 `data\`，与 `--config` 无关。用两个不同配置同时启动两个实例时（自查脚本 qa.ps1 就是这么用的），它们会互相覆盖会话状态；更糟的是 journal.txt——一个实例启动时会把另一个实例接管的窗口当成"自己崩溃前留下的"去还原，位置和样式都会被打乱。全局热键（Alt+1~9）第二个实例注册不了，静默失败，属于 Windows 平台限制，不在本决定范围内。

## 决策

数据目录由实例标签决定：`--config foo.json` → `data-foo\`，无 `--config` → `data\`。`custom.json` 和 `pipeline.json` 保持放在 exe 旁不动——它们是用户数据/配置，本来就该跨实例共享；会话、journal、日志是运行期状态，必须各管各。

代价是 `--doctor` 等诊断命令要记住去对应的目录找日志，README 的「出问题时」一节已注明。

## 后果

- 多实例可以同时跑，互不干扰（热键除外）
- 旧的 `data\session.json` 对带 `--config` 的实例不再生效，首次启动会像新机器一样
- 日志散到多个目录，排错时先确认实例是哪个配置启动的
