# 协同模式：三阶段 agent 流水线

三个 agent 接力完成一个任务，结果回到第一个 agent 判断是否满足需求。

```
需求 →[拆解]→[编码]→[审查]→ 回到拆解判断
                    ↑              │
                    └── 不满足 ────┘
```

## 已定的决定

| # | 决定 | 取值 |
|---|---|---|
| 1 | 三轮之间怎么交接 | **半自动**：程序切到下一个应用 + 把阶段提示词放剪贴板，你按 `Ctrl+V` 回车 |
| 2 | 输出怎么拿到 | **剪贴板监听为主**；监听到 `Ctrl+C` 就自动推进，监听不到退回手动「下一步」 |
| 3 | 流程定义在哪 | `pipeline.json`，可改角色顺序、加阶段、换提示词 |
| 4 | 流水线界面 | 右侧画面顶部一条三段进度条：当前步 / 上一步输出摘要 / 「继续」按钮 |
| 5 | 三个角色怎么来 | **和「已选」解耦**，进协同模式时单独指定 |
| 6 | 一轮跑完 | **停在结果页**（可一键再来一轮）**+ 落一份文件** `.scratch/pipeline-<时间>.md` |
| 7 | 任务怎么输入 | 流程条里的**输入框**，敲完回车开始 |
| 8 | 某步迟迟没动作 | **等 10 分钟**后标记该步「暂停」，回来点一下继续 |
| 9 | 已有「已选」怎么办 | **同一个应用只开一个窗口**：协同角色复用它，谁需要谁接管 |
| 10 | 提示词 | **内置三段模板**，`pipeline.json` 可覆盖 |
| 11 | 循环上限 | **最多 3 轮**，3 轮后强制停下给你看 |

## 状态机

```
Idle ──开始任务──▶ Running(step=0)
Running ──该步完成──▶ step+1 ──▶ Running
Running(末步完成) ──▶ Judging ──满足──▶ Done
                              └─不满足──▶ 轮次+1 ──超 3──▶ Aborted
Running ──10 分钟无动作──▶ Paused ──继续──▶ Running
```

每一步的实际动作只有两件事：**切窗口** + **放剪贴板**。程序不替用户按粘贴和回车（除非将来给某个应用单独做自动化）。

## `pipeline.json`

```json
{
  "maxRounds": 3,
  "stepTimeoutMinutes": 10,
  "steps": [
    { "role": "拆解", "agent": "dsh",    "prompt": "拆解这个需求为可执行的编码任务：{{task}}" },
    { "role": "编码", "agent": "trae",   "prompt": "按下面的任务写代码，只输出代码和必要说明：{{input}}" },
    { "role": "审查", "agent": "qoder",  "prompt": "审查下面的代码是否满足任务要求，逐条指出问题：{{input}}" },
    { "role": "判定", "agent": "dsh",    "prompt": "结合审查意见判断任务是否完成，回答 满足 / 不满足 并说明：{{input}}" }
  ]
}
```

`{{task}}` 是用户输入的需求，`{{input}}` 是上一步的输出。

## 验收标准

- [ ] 输入需求后回车，自动切到第一个角色应用并把提示词放进剪贴板
- [ ] 在应用里按 `Ctrl+C` 复制回复，程序自动推进到下一步
- [ ] 未复制时可按「下一步」手动推进
- [ ] 进度条显示当前步、上一步摘要
- [ ] 判定「不满足」时回到第一步，轮次 +1
- [ ] 3 轮未通过时停止并提示
- [ ] 完成后写入 `.scratch/pipeline-<时间>.md` 并停在结果页
- [ ] 10 分钟无动作转「暂停」，不丢状态

## 还没定的事（实现时需要再问）

- 剪贴板监听的**去重策略**：同一步里你复制了两次怎么办（取最后一次？）
- 判定阶段的**文本解析**：「满足 / 不满足」用关键字匹配还是让用户点按钮
- 流程条的**收起**：跑起来后要不要让出整屏给应用
